# Исследование стенда Saby в браузере

## Безопасность
- Работаю только на тестовых хостах (fix-, test-, dev-, staging- в имени). На рабочие страницы входа (sso.saby.ru, wi.saby.ru) пароль не ввожу — прошу пользователя войти самому и написать «готово».
- Учётные данные не повторяю в ответах и не записываю в brain.
- Чужие выборки только читаю; редактирование открываю и закрываю без сохранения. Свои тестовые данные — с префиксом AT_Claude_, после проверки удаляю.
- Рассылки, начисление бонусов и другие действия с внешним эффектом не выполняю без явного разрешения.

## Браузер
- fix-стенды — сайты повышенного риска: каждое действие требует подтверждения. Сразу предупредить пользователя, экономить шаги, текст читать через get_page_text/javascript, а не скриншотами.
- Эмулировать окно 1440×900, после работы — resize desktop и закрыть вкладку.
- Если координаты кликов не совпадают — кликать по ref из find/read_page.

## Порядок
1. Реестр: весь текст страницы — искать аномалии (счётчик выше лимита, пустые значения «: ;», нет даты/счётчика, одинаковые фильтры с разным результатом).
2. Карточка: меню «⋮», история, операции на пустой выборке.
3. Панель: группы фильтров, подсказки (атрибут title), валидация (пусто, 256 символов, без фильтров), взаимоисключения, И/ИЛИ.
4. Своя выборка: создать → расчёт (окно «Считаем выборку») → остановить → удалить → история.

## Результат
- В карту тестирования: подраздел «Исследование стенда … (дата)» — таблица подозрений Д-N, «Подтверждено», «Новые проверки»; ответы на открытые вопросы отметить.
- Во второй мозг: areas/selections-stands.md, журнал сессии.
- В ответе пользователю: главные подозрения, что подтвердилось, что не проверено и почему.
